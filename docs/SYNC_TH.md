# ซิงก์ผ่าน Google Drive และรายงาน Google Docs

รุ่น 3 เพิ่มการเปิดและแก้ไขประชุมข้ามเครื่อง ไม่ต้องสมัครสมาชิกใหม่ แต่ต้องใช้รหัสเชื่อมต่อ APP_TOKEN เพื่อป้องกันการเข้าถึงข้อมูล ผู้ที่มีรหัสนี้มีสิทธิ์อ่านและแก้ไขข้อมูลทั้งหมดของแอป

## ตั้งค่าครั้งแรก

1. ทำตามคู่มือ INSTALL_TH.md เพื่อสร้างโปรเจกต์ Google Apps Script ด้วยบัญชี Google ของคุณ
2. แทนเนื้อหา Code.gs ทั้งไฟล์ด้วยรุ่นล่าสุดจาก repository แล้วบันทึก ใช้ V8 runtime
3. ใน Project Settings > Script Properties ตั้ง APP_TOKEN เป็นรหัสสุ่มอย่างน้อย 32 ตัวอักษร เก็บเป็นความลับ GEMINI_API_KEY จำเป็นเฉพาะเมื่อใช้ AI ห้ามใส่ key นี้ในเว็บ
4. เลือกฟังก์ชัน authorizeSetup แล้วกด Run ตรวจสอบและยืนยันสิทธิ์ Google ด้วยตัวเอง ฟังก์ชันนี้เตรียมโฟลเดอร์และทดสอบสิทธิ์สร้างเอกสาร
5. Deploy เป็น Web app ตาม INSTALL_TH.md โดย Execute as เป็นเจ้าของ หากเคย Deploy แล้วให้ใช้ Manage deployments > Edit > New version > Deploy การบันทึกโค้ดอย่างเดียวไม่อัปเดตเว็บแอป
6. คัดลอก URL ที่ลงท้าย /exec เปิดแอป > ตั้งค่า ใส่ URL และ APP_TOKEN เปิดตัวเลือกซิงก์ Drive การเปิดตัวเลือกนี้อนุญาตให้อัปโหลดข้อความ สรุป และเสียงทั้งหมดของประชุม
7. ตัวเลือก Google Docs อัตโนมัติจะสร้างรายงานหลังซิงก์และอัปเดตเอกสารเดิม ปิดได้หากไม่ต้องการ รายงานใช้สรุปที่มีอยู่ ไม่เรียก AI เพื่อสร้างสรุปอัตโนมัติ
8. กดซิงก์ รอผลสำเร็จก่อนสลับเครื่อง บนมือถือใส่ URL และรหัสเดียวกันแล้วกดซิงก์ รหัสอยู่ในหน่วยความจำของแท็บ ต้องใส่ใหม่เมื่อเปิดใหม่

## ใช้งานและแก้ปัญหา

เมื่อแก้ข้อมูล แอปจะเตรียมซิงก์หลังประมาณ 3 วินาทีเมื่อไม่มีงานอื่น ระหว่างบันทึกเสียงยังเก็บในเครื่อง ซิงก์เมื่อหยุดแล้ว แอปตรวจข้อมูลขณะเปิดหน้าใช้งานทุกประมาณ 60 วินาที และเมื่อกลับมาออนไลน์ ไม่มีบริการซิงก์ต่อเมื่อปิดแอปหรือเครื่องพัก

ถ้าสองเครื่องแก้ประชุมเดียวกัน แอปจะเตือนและไม่เขียนทับเงียบ ๆ ให้สำรอง JSON ก่อนเลือกใช้ข้อมูลจากคลาวด์ หรือเก็บข้อมูลในเครื่องเป็นประชุมใหม่ JSON ไม่รวมเสียง ต้องดาวน์โหลดเสียงสำรองแยก

เสียงใน Drive เก็บเป็นบล็อกไบนารี แอปตรวจ SHA-256 และประกอบกลับสำหรับฟังหรือดาวน์โหลด ไม่ใช่ไฟล์เสียงประชุมที่เปิดใน Drive ได้ทันที เสียงที่ยังไม่เคยโหลดลงเครื่องต้องมีอินเทอร์เน็ต การส่งออกรายงานแบบเดิมสามารถแนบไฟล์เสียงธรรมดาภายใต้ขนาดที่แอปรองรับได้

รายงาน Docs ที่สร้างอัตโนมัติถูกเขียนเนื้อหาใหม่เมื่อข้อมูลประชุมเปลี่ยน หากแก้รายงานใน Docs เอง การซิงก์ครั้งถัดไปอาจเขียนทับข้อความนั้น ให้แก้ในแอปหรือทำสำเนา Docs แยกไว้ หากสร้างรายงานล้มเหลว ข้อมูลประชุมที่ซิงก์สำเร็จยังอยู่ และแอปแจ้งเตือนให้ตรวจสิทธิ์/โควตาแล้วซิงก์ใหม่

การลบเฉพาะเครื่องไม่ลบคลาวด์ ข้อมูลอาจกลับมาเมื่อซิงก์ การลบทุกเครื่องสร้างสถานะลบเพื่อกันข้อมูลกลับมา แต่ยังเก็บข้อมูลและเสียงเดิมใน Drive รวมถึง Docs ไม่ใช่การลบถาวร ต้องจัดการการลบถาวรในบัญชีเจ้าของอย่างระมัดระวัง

ห้ามเปลี่ยนปลายทางของประชุมที่ผูกกับคลาวด์เดิมเพื่อส่งต่อโดยไม่ตั้งใจ ใช้ส่งออก/นำเข้าเป็นประชุมใหม่เมื่อต้องย้ายระบบ การซิงก์ไม่แทนสำเนาสำรองอิสระ

## ขอบเขตและการตรวจสอบ

เสียงแต่ละช่วงไม่เกิน 256 MiB และรวมไม่เกิน 2,000 บล็อกขนาด 1 MiB ต่อประชุม เมทาดาทาไม่เกิน 2 MiB จำนวนประชุมไม่เกิน 2,000 รายงานอัตโนมัติไม่เกิน 5,000 ข้อความและข้อมูลประมาณ 500 KB ข้อจำกัด Google Apps Script และโควตาบัญชียังใช้ตามปกติ ไม่รับประกันการประชุมยาวมากโดยไม่ได้ทดลองกับอุปกรณ์จริง

กรณีสร้าง Docs ถูกขัดจังหวะก่อนบันทึกหมายเลขเอกสาร ระบบหยุดสร้างซ้ำเพื่อกันเอกสารซ้ำ เจ้าของต้องตรวจ Drive ก่อนแก้สถานะ ห้ามลบ state.json โดยเดาสุ่ม

การทดสอบอัตโนมัติใช้บริการ Google จำลอง ต้องทดสอบกับ deployment และอุปกรณ์จริงก่อนใช้ข้อมูลสำคัญ ผู้พัฒนาไม่ได้รับสิทธิ์เข้าบัญชี Google จากการอนุญาตในแชต
