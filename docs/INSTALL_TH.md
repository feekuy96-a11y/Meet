# คู่มือติดตั้ง MeetNote TH สำหรับผู้เริ่มต้น

## 1. ระบบนี้ทำอะไร และข้อมูลไปที่ไหน

MeetNote เป็นเว็บบันทึกการประชุมภาษาไทย ไม่ต้องมีเซิร์ฟเวอร์ฐานข้อมูลส่วนตัว

- **บันทึกเสียง / พิมพ์ / ประวัติ:** เก็บใน IndexedDB ของเบราว์เซอร์บนเครื่องที่ใช้ ไม่ได้อัปโหลดทันที
- **ถอดเสียงสด:** ใช้บริการ SpeechRecognition ของเบราว์เซอร์ อาจส่งเสียงไปยังผู้ให้บริการเบราว์เซอร์ ต้องใช้อินเทอร์เน็ตและรองรับภาษาไทย ไม่ใช่การถอดเสียงออฟไลน์
- **สรุป AI:** เมื่อกดยืนยันส่งข้อมูล เว็บส่งข้อความและเสียงถ้าเปิดไว้ ไป Apps Script แล้วส่งต่อ Gemini
- **สร้างเอกสาร:** เมื่อกดยืนยัน เว็บส่งข้อมูลไป Apps Script เพื่อสร้างไฟล์ใน Google Drive ของบัญชีเจ้าของสคริปต์
- **JSON:** สำรองข้อความ ผู้พูด เวลา และสรุปเท่านั้น ไม่รวมเสียง ต้องดาวน์โหลดเสียงแต่ละช่วงแยก

ต้องแจ้งและได้รับความยินยอมจากผู้เข้าร่วมก่อนบันทึกหรือส่งข้อมูลไปบริการภายนอก ปฏิบัติตามกฎขององค์กรเกี่ยวกับข้อมูลส่วนบุคคลและความลับ

ระบบนี้เหมาะสำหรับเจ้าของคนเดียวหรือทีมเล็กที่ไว้ใจกัน มี **รหัสผ่านร่วมกัน ไม่ใช่ระบบบัญชีผู้ใช้** ผู้มี URL และรหัสสามารถใช้โควตา Gemini และสร้างไฟล์ใน Drive ของเจ้าของได้ ยังไม่มีการแยกสิทธิ์ผู้ใช้หรือเก็บประวัติผู้ใช้งาน หากจะเปิดให้บุคคลทั่วไปใช้ ให้พัฒนาระบบล็อกอิน สิทธิ์รายผู้ใช้ และจำกัดค่าใช้จ่ายก่อน

## 2. สิ่งที่ต้องเตรียม

1. คอมพิวเตอร์ที่มี Chrome หรือ Edge รุ่นปัจจุบัน และไมโครโฟน แนะนำเริ่มทดสอบด้วยคอมพิวเตอร์ก่อน
2. บัญชี Google ที่มี Google Drive และเข้าถึง Google Apps Script ได้ แนะนำบัญชีสำหรับระบบนี้แยกจากเอกสารสำคัญอื่น
3. หากต้องการ AI: API key จาก Google AI Studio และโควตาของโมเดลที่เลือก การเปิด Billing อาจมีค่าใช้จ่าย ตรวจราคาปัจจุบันก่อนเปิด
4. สำหรับเว็บ: บัญชี GitHub ถ้าจะใช้ GitHub Pages หรือ Python 3 หากจะทดลองเฉพาะเครื่อง
5. แตกไฟล์ `MeetNote-reviewed.zip` ลงโฟลเดอร์หนึ่ง เช่น `MeetNote` **อย่าย้ายไฟล์ทุกอย่างมารวมกัน**

โครงสร้างที่ถูกต้อง:

```text
MeetNote/
  index.html
  sw.js
  manifest.webmanifest
  Code.gs
  css/
    style.css
    accessibility.css
  js/
    app.js
    model.js
    api.js
    audio.js
    db.js
    ui.js
    worklet.js
  icons/
    icon-192.png
    icon-512.png
  docs/
```

ไฟล์ `worklet.js` คงไว้จากต้นฉบับเพื่ออ้างอิง แต่เวอร์ชันนี้ไม่เรียกใช้มัน เพราะมันไม่สามารถรับประกันการบันทึกขณะปิดจอได้

## 3. ทดลองเปิดเว็บก่อน โดยยังไม่ใช้ AI

**อย่าดับเบิลคลิก index.html เพื่อเปิดแบบ file://** จะเกิดปัญหาการโหลด JavaScript และไมโครโฟน

### Windows

1. ติดตั้ง Python 3 จาก <https://www.python.org/downloads/> ให้เลือกเพิ่ม Python ใน PATH หากหน้าติดตั้งมีตัวเลือกนี้
2. เปิดโฟลเดอร์ MeetNote ใน File Explorer
3. คลิกช่องที่อยู่ด้านบน พิมพ์ `cmd` แล้วกด Enter จะเปิดหน้าต่างคำสั่งในโฟลเดอร์นี้
4. พิมพ์คำสั่ง:

   ```bat
   py -m http.server 8080 --bind 127.0.0.1
   ```

5. เปิด Chrome แล้วพิมพ์ `http://localhost:8080` ในช่องที่อยู่
6. หาก `py` ใช้ไม่ได้ ลอง `python -m http.server 8080 --bind 127.0.0.1` หลังติดตั้ง Python

### macOS / Linux

1. ติดตั้ง Python 3 หากยังไม่มี
2. เปิด Terminal พิมพ์ `cd ` แล้วลากโฟลเดอร์ MeetNote มาวางต่อท้าย กด Enter
3. รัน:

   ```sh
   python3 -m http.server 8080 --bind 127.0.0.1
   ```

4. เปิด Chrome ไปที่ `http://localhost:8080`

หน้าต่างคำสั่งต้องเปิดค้างไว้ระหว่างใช้เว็บ กด `Ctrl+C` เมื่อต้องการหยุดเซิร์ฟเวอร์ เซิร์ฟเวอร์นี้สำหรับทดลองในเครื่อง ไม่ใช่เซิร์ฟเวอร์สาธารณะ ถ้าเปลี่ยนจาก localhost เป็น 127.0.0.1 หรือเปลี่ยนพอร์ต ประวัติจะอยู่คนละพื้นที่เก็บข้อมูล

### ทดสอบขั้นต่ำ

1. ใส่ชื่อประชุม เช่น “ทดลองครั้งแรก”
2. พิมพ์ข้อความในช่องบันทึกย่อ กดบันทึก
3. ปิดสวิตช์ถอดเสียงสดก่อน เพื่อทดสอบการบันทึกเสียงอย่างเดียว
4. กดเริ่มบันทึก อนุญาตไมโครโฟน พูดประมาณ 10 วินาที
5. กดพัก รอ 3 วินาที แล้วกดทำต่อ พูดอีกครั้ง
6. กดจบการประชุมและยืนยัน รอคำว่า “พร้อม”
7. กดฟังเสียงแต่ละช่วง และดาวน์โหลดไฟล์เสียงไว้
8. เปิดแท็บสรุป เลือก JSON แล้วกดดาวน์โหลด ไฟล์นี้ไม่มีเสียง
9. รีโหลดหน้าเว็บ ตรวจชื่อ ข้อความ และเสียง เปิดคลังประวัติเพื่อตรวจรายการ

หากไม่ต้องการ AI หรือ Google Docs ใช้งานเฉพาะขั้นตอนนี้ได้ ไม่จำเป็นต้องสร้าง Apps Script

## 4. ตั้งค่า Gemini โดยไม่ใส่ API key ในเว็บ

1. เปิด <https://aistudio.google.com/> ด้วยบัญชี Google
2. เข้าเมนูสำหรับสร้าง API key เลือกโปรเจกต์ที่ต้องการใช้ และสร้าง key ชื่อเมนูอาจเปลี่ยนตาม Google
3. เก็บ key ในที่ปลอดภัย **อย่าส่ง key ในแชต อย่าใส่ใน GitHub และอย่าใส่ในไฟล์ app.js หรือ Code.gs**
4. ตรวจว่าบัญชีและโปรเจกต์ของคุณมีสิทธิ์ใช้ Gemini API และโมเดลที่จะตั้งค่า พร้อมโควตาเพียงพอ
5. จำกัด API key ให้ใช้กับ Generative Language API ถ้าหน้าตั้งค่ารองรับ อย่าตั้งข้อจำกัด HTTP referrer แบบเว็บเบราว์เซอร์ เพราะคำขอจริงออกจาก Apps Script
6. ตั้งการแจ้งเตือนค่าใช้จ่ายใน Google Cloud หากเปิด Billing การแจ้งเตือนไม่ใช่เพดานตัดการใช้งาน ต้องตั้งโควตาที่เหมาะสมด้วย

โมเดลเริ่มต้นในโค้ดคือ `gemini-2.5-flash` **ไม่สามารถยืนยันสิทธิ์หรือความพร้อมใช้ในโปรเจกต์คุณจากเครื่องทดสอบนี้ได้** ตรวจชื่อและการรองรับเสียง/JSON จากเอกสารปัจจุบันที่ <https://ai.google.dev/gemini-api/docs/models> ถ้าโมเดลหยุดให้บริการ ให้แก้ค่า `GEMINI_MODEL` ฝั่ง Apps Script โดยไม่ต้องแก้หน้าเว็บ

## 5. สร้าง Google Apps Script

1. เปิด <https://script.google.com/> แล้วเลือกสร้างโปรเจกต์ใหม่
2. ตั้งชื่อโปรเจกต์ เช่น `MeetNote TH Backend`
3. เปิดไฟล์ `Code.gs` ในโปรเจกต์ ลบโค้ดตัวอย่างภายในไฟล์
4. เปิด `Code.gs` จากชุดไฟล์ที่ได้รับ ด้วยโปรแกรมแก้ไขข้อความ เช่น Notepad หรือ VS Code คัดลอก **ทั้งไฟล์** ไปวางแทน
5. กดบันทึก
6. เปิด **Project Settings / การตั้งค่าโปรเจกต์** (รูปเฟืองทางซ้าย)
7. หา **Script Properties / คุณสมบัติสคริปต์** กดเพิ่มค่า ใส่:

   | ชื่อ              | ค่าที่ใส่                                                                                                  |
   | ----------------- | ---------------------------------------------------------------------------------------------------------- |
   | `APP_TOKEN`       | รหัสสุ่มอย่างน้อย 32 ตัวอักษร แนะนำ 40–64 ตัวอักษร ใช้ตัวสร้างรหัสของ password manager เก็บเฉพาะที่ปลอดภัย |
   | `GEMINI_API_KEY`  | API key ที่สร้างในข้อ 4                                                                                    |
   | `GEMINI_MODEL`    | ชื่อโมเดลที่โปรเจกต์ใช้ได้ เช่น `gemini-2.5-flash`                                                         |
   | `DRIVE_FOLDER_ID` | เว้นไว้ได้ ระบบสร้างโฟลเดอร์ใหม่ให้ หากใส่เองต้องเป็น ID ของโฟลเดอร์ที่เจ้าของเขียนได้                     |

   **ชื่อค่าต้องตรงทุกตัว** ไม่ใส่เครื่องหมายอัญประกาศรอบค่า ถ้าใช้เฉพาะ Docs ไม่ต้องตั้ง Gemini key จนกว่าจะต้องสรุป AI

8. บันทึกคุณสมบัติสคริปต์ ไม่ใส่ค่าลับในตัวโค้ด
9. กลับไปหน้า Editor เลือกฟังก์ชัน `authorizeSetup` ในช่องด้านบน แล้วกด Run / เรียกใช้
10. Google จะขออนุญาตเข้า Drive, Docs และเรียกบริการภายนอก ตรวจว่าเป็นโปรเจกต์ของคุณและโค้ดที่คุณวาง แล้วอนุญาต ฟังก์ชันนี้สร้างโฟลเดอร์หากไม่มี สร้างเอกสารทดสอบหนึ่งไฟล์แล้วย้ายไปถังขยะ และเรียกโดเมน Gemini โดยไม่ส่ง key หรือข้อมูลประชุม
11. ถ้าระบบองค์กรไม่ให้อนุญาตแอปที่ยังไม่ผ่านการตรวจสอบ **อย่าข้ามนโยบายองค์กร** ติดต่อผู้ดูแลบัญชี Google Workspace

ระบบใช้สิทธิ์ Drive/Docs ของเจ้าของสคริปต์ ซึ่งกว้างกว่าสิทธิ์เฉพาะโฟลเดอร์ในแอป เจ้าของโปรเจกต์และผู้มีสิทธิ์แก้ Apps Script สามารถอ่าน Script Properties ได้ อย่าให้สิทธิ์แก้โปรเจกต์กับคนที่ไม่ควรเห็น API key

### โฟลเดอร์และการแชร์

ใช้โฟลเดอร์ใหม่ที่ไม่ได้แชร์สำหรับข้อมูลลับ ค่า `DRIVE_FOLDER_ID` คือส่วน ID ใน URL `https://drive.google.com/drive/folders/ID` ไม่ใช่ URL ทั้งเส้น

ไฟล์ใหม่ไม่ได้เรียกคำสั่งแชร์เอง แต่ **อาจสืบทอดสิทธิ์จากโฟลเดอร์ที่แชร์ไว้** ตรวจสิทธิ์โฟลเดอร์และไฟล์จริงก่อนส่งข้อมูลสำคัญ ไม่แนะนำ Shared Drive สำหรับการติดตั้งครั้งแรก การลบประวัติในเว็บไม่ลบไฟล์บน Google Drive

## 6. Deploy เป็น Web App

1. กด **Deploy / ทำให้ใช้งานได้ → New deployment / การทำให้ใช้งานได้รายการใหม่**
2. เลือกชนิด **Web app / เว็บแอป** (หากไม่เห็น ให้กดรูปเฟืองเลือกชนิด)
3. ใส่คำอธิบาย เช่น `MeetNote v2`
4. **Execute as / เรียกใช้ในฐานะ:** เลือก **Me / ฉัน** (เจ้าของสคริปต์)
5. **Who has access / ผู้มีสิทธิ์เข้าถึง:** เลือกตัวเลือก **Anyone / ทุกคน** ที่อนุญาตให้เรียกโดยไม่ล็อกอิน Google เว็บภายนอกต้องใช้ตัวเลือกนี้แล้วตรวจ APP_TOKEN ภายในสคริปต์
6. หากบัญชีของคุณไม่มีตัวเลือกนี้เพราะนโยบายองค์กร การเชื่อมต่อจากเว็บภายนอกนี้อาจใช้ไม่ได้ ต้องให้ผู้ดูแลเลือกแนวทางที่องค์กรอนุญาต ไม่ใช่แก้ด้วยการตั้ง `no-cors`
7. กด Deploy อนุญาตสิทธิ์หากมีการถาม
8. คัดลอก **Web app URL** รูปแบบ:

   ```text
   https://script.google.com/macros/s/DEPLOYMENT_ID/exec
   ```

   ใช้ `/exec` เท่านั้น ไม่ใช้ `/dev` ไม่ใช้ URL หน้า Editor

9. เปิด URL นี้ในเบราว์เซอร์ ควรเห็น JSON ที่มี `"ok":true`, `"service":"MeetNote TH"`, `"version":2` ขั้นตอนนี้ตรวจเพียงการ Deploy ไม่ได้ยืนยันสิทธิ์ API หรือการสร้างไฟล์
10. อย่าเผยแพร่ APP_TOKEN คู่กับ URL ในที่สาธารณะ Endpoint เปิดให้ใครก็เรียกได้ แต่คำสั่งสรุปและสร้างเอกสารตรวจ APP_TOKEN ก่อนทำงาน การบล็อก Origin/CORS ไม่ใช่ระบบล็อกอิน

### เมื่อแก้ Code.gs ในภายหลัง

บันทึกไฟล์ → Deploy → Manage deployments → เลือกรายการเดิม → Edit → Version เลือก **New version** → Deploy โดยปกติใช้ URL เดิมต่อได้ แก้ใน Editor อย่างเดียวไม่ได้เปลี่ยนเวอร์ชัน `/exec` ที่ใช้อยู่

## 7. เชื่อมเว็บกับ Backend

1. กลับไปเว็บ MeetNote กดปุ่มเฟือง ⚙️
2. ใส่ Web app URL จากข้อ 6
3. ใส่รหัส `APP_TOKEN` **ไม่ใช่ GEMINI_API_KEY**
4. การส่งเสียงปิดไว้เป็นค่าเริ่มต้น หากต้องการให้ Gemini วิเคราะห์เสียงหรืออัปโหลดเสียงไป Drive ให้เปิด “ส่งเสียงให้ Gemini และ Drive”
5. กดบันทึก รหัสผ่านอยู่ในหน่วยความจำแท็บเท่านั้น รีโหลด ปิดแท็บ หรือเปิดแท็บใหม่ต้องใส่รหัสอีกครั้ง URL และตัวเลือกอื่นเก็บในเครื่อง
6. ทำประชุมทดสอบด้วยข้อมูลที่ไม่เป็นความลับ
7. กดสรุป AI ตรวจข้อความในหน้าต่างยืนยัน แล้วกดส่งข้อมูล
8. ตรวจสรุป โดยเฉพาะมติ ผู้รับผิดชอบ กำหนดเวลา และการระบุผู้พูด AI อาจผิดหรือถูกหลอกด้วยเนื้อหาที่ป้อน แม้มีคำสั่งป้องกันแล้ว
9. เลือกฉบับสรุป / ฉบับเต็ม / สองไฟล์ กดสร้างเอกสาร ยืนยัน แล้วเปิดลิงก์ตรวจเอกสารจริงใน Drive
10. “สองไฟล์” สร้างสรุปหนึ่งไฟล์และบทสนทนาอีกหนึ่งไฟล์ เสียงอัปโหลดครั้งเดียวพร้อมลิงก์ในฉบับเต็ม ชื่อไฟล์เสียงใช้ชนิดจริง เช่น `.webm` หรือ `.m4a`

หากสรุปต้องใช้เสียงอย่างเดียวและไม่มีข้อความ ให้เปิดส่งเสียงและจบการบันทึกก่อนกดสรุป ถ้าเสียงใหญ่เกิน 8 MB หรือมีมากกว่า 20 ช่วง ให้ปิดส่งเสียงและใช้ข้อความแทน **ระบบจะไม่เงียบแล้วเปลี่ยนเป็นข้อความเอง** หากไม่มีข้อความต้องแบ่งการประชุมหรือใช้บริการถอดเสียงภายนอกที่องค์กรอนุญาต

## 8. เผยแพร่เว็บด้วย GitHub Pages (ทางเลือก)

หากใช้ repository `feekuy96-a11y/Meet` อยู่แล้ว ให้อัปโหลดไฟล์ไป repository เดิม ไม่จำเป็นต้องสร้างใหม่ ขั้นตอนนี้ไม่ได้ทำ push หรือเผยแพร่ให้โดยอัตโนมัติ

1. ลงชื่อเข้า GitHub เปิด repository `Meet`
2. เลือก **Add file → Upload files** หรือใช้ GitHub Desktop เพื่ออัปโหลดโครงสร้างไฟล์ให้เหมือนข้อ 2
3. ไฟล์ `index.html` ต้องอยู่ราก repository และไฟล์ JavaScript อยู่ในโฟลเดอร์ `js/` อย่าอัปโหลดเฉพาะโฟลเดอร์ซ้อน `MeetNote/` อีกชั้น
4. ตรวจว่าไม่มี API key, APP_TOKEN, `.env`, JSON สำรองประชุม หรือไฟล์เสียงประชุมในไฟล์ที่จะอัปโหลด โค้ด Code.gs ชุดนี้ไม่มีค่าลับ แต่ค่า Script Properties ไม่ควรนำออกมาใส่ Git
5. บันทึกการอัปโหลดลง branch `main`
6. ไป **Settings → Pages → Build and deployment** เลือกเผยแพร่จาก branch `main` และโฟลเดอร์ `/ (root)` แล้วกด Save
7. รอ GitHub สร้างเว็บ เปิด URL HTTPS ที่ GitHub แสดง
8. อนุญาตไมโครโฟนบน URL ใหม่นี้ และใส่การตั้งค่า Apps Script อีกครั้ง ประวัติจาก localhost ไม่ย้ายตาม ต้องส่งออก JSON จากเว็บเดิมแล้วนำเข้าเว็บใหม่ ส่วนเสียงสำรองเก็บเป็นไฟล์แยก ไม่มีการนำเข้าเสียงในรุ่นนี้

GitHub Pages เป็นโฮสต์ไฟล์สาธารณะ แม้ต้นทาง repository มีตัวเลือก private ในแผนบางแบบ ก็ต้องตรวจสิทธิ์การเข้าถึง Pages ด้วย ไฟล์เว็บไม่ควรมีค่าลับ ไม่ต้องรัน Node.js บนโฮสต์ เว็บทำงานเป็น static files

หากองค์กรกำหนดใช้โฮสต์อื่น ให้ใช้ HTTPS และเสิร์ฟ MIME ของ `.js` เป็น JavaScript, `.css` เป็น CSS, `.webmanifest` เป็น JSON/manifest แนะนำตั้ง header `Content-Security-Policy` เพิ่ม `frame-ancestors 'none'` (คำสั่งนี้ใช้ผ่าน meta ไม่ได้), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` และ `Permissions-Policy: microphone=(self)` โดยคงโดเมน connect-src ของ Apps Script ตาม index.html

## 9. การใช้งานประจำวันและการสำรอง

เปิดแท็บ MeetNote ที่แก้ข้อมูลได้ครั้งละหนึ่งแท็บต่อเว็บไซต์ เพื่อไม่เขียนข้อมูลทับกัน ถ้าแท็บใหม่แจ้งว่ามีแท็บเปิดอยู่ ให้ใช้แท็บเดิมหรือปิดแท็บเดิมแล้วโหลดแท็บใหม่ ต้องใช้เบราว์เซอร์ที่รองรับ Web Locks (Chrome/Edge รุ่นปัจจุบันบน HTTPS/localhost)

- เลือกผู้พูดก่อนพูด หรือกดเลข 1–9 เมื่อไม่ได้พิมพ์ข้อความ ระบบ **ไม่ได้วิเคราะห์หรือยืนยันตัวตนจากเสียง** สามารถแก้ผู้พูดของแต่ละข้อความภายหลังได้
- พักแล้วเวลาประชุมและเสียงจะหยุดพัก กดทำต่อก่อนพูดต่อ
- จบประชุม รอให้พร้อม ฟังเสียง ตรวจข้อความ และสำรอง JSON **พร้อมเสียงทุกช่วง**
- ตั้งชื่อไฟล์สำรองให้มีวันประชุม เก็บในพื้นที่สำรองที่มีสิทธิ์จำกัด อย่าใช้ชื่อเป็นข้อมูลลับถ้าต้องแชร์ไฟล์
- JSON นำเข้าได้จาก “คลังประวัติ → นำเข้า JSON” จะสร้างรายการใหม่ ไม่ทับรายการเดิม ไม่รวมเสียง และไม่ส่งข้อมูลไป Google
- เปลี่ยนข้อความหรือผู้พูดแล้วสรุปเก่าจะถูกล้าง เพื่อไม่ใช้รายงานที่ไม่ตรงกับข้อมูล ต้องสรุปใหม่
- Word `.doc` เป็นเอกสาร HTML สำหรับเปิดด้วย Word ไม่ใช่ `.docx` จริง Word อาจแจ้งเตือนว่ารูปแบบกับนามสกุลไม่ตรง สามารถเปิดและ Save As เป็น `.docx` ได้
- PDF เปิดหน้าต่างพิมพ์ ให้เลือก **Save as PDF / บันทึกเป็น PDF** ตรวจหน้าตัวอย่างก่อนบันทึก
- หากจะใช้ขณะออฟไลน์ ให้เปิดเว็บออนไลน์ก่อนอย่างน้อยหนึ่งครั้ง รอโหลดครบ แล้วเปิดใหม่ทดสอบ เว็บและการเก็บข้อมูลในเครื่องทำงานได้ แต่ AI, Docs และถอดเสียงของเบราว์เซอร์อาจทำงานไม่ได้
- ติดตั้งเป็นแอปได้ผ่านเมนู Install app ของ Chrome/Edge เมื่อเบราว์เซอร์เสนอ ไม่มีข้อรับประกันว่ามือถือทุกเครื่องจะติดตั้งได้เหมือนกัน
- อย่าปิดแท็บ ล้างข้อมูลเว็บไซต์ เปลี่ยนโดเมน หรือใช้โหมดไม่ระบุตัวตนโดยไม่สำรอง ข้อมูลไม่ได้ซิงก์ข้ามเครื่องหรือบัญชี Google

## 10. ข้อจำกัดและการกู้ข้อมูล

### ปิดจอ / พักเครื่อง / แท็บถูกปิด

เบราว์เซอร์และระบบปฏิบัติการอาจหยุดหรือเลื่อนการส่งช่วงเสียงเมื่อทำงานเบื้องหลัง **ไม่รับประกันบันทึกต่อเมื่อปิดจอ** เปิดหน้าจอไว้ ปิดโหมดประหยัดพลังงานตามนโยบายอุปกรณ์ และทดสอบอุปกรณ์จริงก่อนประชุมสำคัญ ใช้เครื่องบันทึกสำรองสำหรับงานที่พลาดไม่ได้

เสียงเขียนลงฐานข้อมูลประมาณทุก 2 วินาที แต่เวลาจริงอาจถูกเลื่อนโดยเบราว์เซอร์ การปิดแท็บอย่างกะทันหันกู้ได้เฉพาะช่วงที่ฐานข้อมูลเขียนสำเร็จแล้ว ช่วงท้ายที่ยังอยู่ในตัวบันทึกอาจหาย เปิดเว็บใหม่แล้วฟังเสียงที่กู้ได้ ไม่สัญญาว่าจะกู้ทุกวินาที

### พื้นที่เต็ม / บันทึกเสียงบางช่วงไม่ได้

ระบบหยุดบันทึกและเปิดหน้าต่างกู้ข้อมูล อย่าปิดแท็บ

1. กดดาวน์โหลดเสียงกู้คืน แล้วตรวจว่าไฟล์อยู่ในโฟลเดอร์ Downloads และเปิดฟังได้
2. ยืนยันเก็บสำรองแล้ว **หลังตรวจไฟล์จริงเท่านั้น**
3. หรือเพิ่มพื้นที่ว่างโดยไม่ลบข้อมูลเว็บไซต์ MeetNote แล้วกดลองบันทึกอีกครั้ง
4. อย่าล้าง IndexedDB หรือข้อมูลเว็บไซต์เพื่อแก้พื้นที่เต็มก่อนสำรอง เพราะจะลบประชุมและเสียง
5. หากดาวน์โหลดไม่ได้หรือฐานข้อมูลอ่านไม่ได้ ต้องหยุดใช้งานและรักษาแท็บไว้เพื่อให้ผู้ดูแลช่วยกู้ ไม่มีข้อรับประกันกู้ข้อมูลเมื่อพื้นที่หรืออุปกรณ์เสียหาย

### รอนานเกิน 90 วินาทีขณะสร้างเอกสาร

Apps Script อาจยังทำงานอยู่แม้หน้าเว็บหยุดรอ ตรวจ Drive และรอให้การทำงานจบก่อนลองใหม่ คำขอเดิมของประชุมเดิมที่ข้อมูลไม่เปลี่ยนจะใช้ ID เดิมซึ่งบันทึกลงเครื่องแล้ว เซิร์ฟเวอร์เก็บประวัติ ID ไม่เกิน 100 คำขอเป็นเวลา 30 วัน เพื่อลดไฟล์ซ้ำ การลบข้อมูลเว็บ/นำเข้ารายการใหม่/แก้ข้อมูล/เกินช่วงเก็บประวัติอาจสร้าง ID ใหม่และทำให้มีไฟล์ซ้ำได้

ถ้าขึ้น “สร้างเอกสารไม่ครบ” ระบบไม่สร้างซ้ำอัตโนมัติสำหรับ ID เดิม เพราะไม่รู้ว่าการทำงานรอบก่อนสร้างไฟล์ไปถึงไหน ให้ผู้ดูแลตรวจ Drive และ Script Properties ที่ชื่อขึ้นต้น `JOB_` ค่า `fileIds` และ `cleanupFailed` ช่วยหาไฟล์ตกค้าง ลบเฉพาะ JOB ที่วิเคราะห์แล้วว่าปลอดภัยจะเริ่มใหม่ ห้ามลบประวัติทั้งหมดโดยเดา เพราะอาจทำให้เอกสารซ้ำ

### อัปเดตเว็บแล้วเห็นรุ่นเก่า

Service worker รอแท็บเดิมปิดก่อนเปลี่ยนรุ่น เพื่อไม่เปลี่ยนไฟล์กลางการบันทึก จบและสำรองประชุม ปิดแท็บแอปทั้งหมดแล้วเปิดใหม่ ทุกครั้งที่แก้ไฟล์ static ผู้พัฒนาต้องเปลี่ยนค่า `CACHE` ใน `sw.js` ด้วย ถ้าไม่จำเป็นอย่าล้างข้อมูลเว็บไซต์ เพราะจะลบประวัติด้วย

## 12. ทดสอบและพัฒนาต่อ (สำหรับผู้ดูแล)

การใช้เว็บไม่ต้องติดตั้ง npm แต่การรันชุดทดสอบต้องมี Node.js รุ่น 22 ขึ้นไป แนะนำรุ่น LTS ที่ยังได้รับการสนับสนุน

```sh
# รันในโฟลเดอร์ MeetNote
npm ci
npm test
npx playwright install chromium
```

เปิด Terminal หนึ่งรันเซิร์ฟเวอร์:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

อีก Terminal ในโฟลเดอร์เดียวกัน:

```sh
npm run test:browser
```

บน Linux ที่มี Chromium อยู่แล้วใช้ `CHROMIUM_PATH=/usr/bin/chromium npm run test:browser` ได้ ถ้าระบบใช้พอร์ตอื่นตั้ง `TEST_BASE_URL` เป็น URL ของเซิร์ฟเวอร์ทดสอบ ชุดทดสอบเบราว์เซอร์สร้างเสียงจำลองและใช้ backend จำลอง ไม่ส่งข้อมูลเข้าบัญชี Google จริง

ดู Console ด้วย F12 → Console และ Network หากต้องส่งภาพข้อผิดพลาด ให้ปิดบังรหัสผ่าน เนื้อหาประชุม และรายละเอียดส่วนบุคคลก่อน ไม่ส่ง request body เพราะมี APP_TOKEN และข้อมูลประชุม
